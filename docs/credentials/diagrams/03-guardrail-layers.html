Cluster credentials · 03 · Compensating layers

What stands between a misused credential and kiac-dev

No layer is trusted alone. Each narrows what the one above lets through; what is left is a bounded set of writes, gated on ownership and recorded.

Before (until 2026-10-12)

One kubernetes.io/service-account-token that never expired, in four places (kiac-dev, Infisical, a kind-prod Secret, the process env), sent without TLS verification. It could create PipelineRuns anywhere, which made it cluster-admin, and any signed-in user could use it through the proxy.

Now

Nothing is stored. Reads use a token that rotates every few minutes; each write mints its own. The cluster accepts only those two accounts, splits what they may do, and checks the shape of every write. Since P6 (2026-10-30) neither can write a PipelineRun: Tekton writes go through glidepath-api.

Kill switch

Delete the jwt entry in kiac-dev's /etc/kubernetes/authn/config.yaml: the API server reloads it and every kind-prod token stops working at once.
