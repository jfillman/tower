Cluster credentials · 01 · Architecture

How Tower reaches kiac-dev without a stored token

Backstage runs on kind-prod. kiac-dev trusts kind-prod's ServiceAccount issuer, so a kind-prod token addressed to kiac-dev is accepted there: the pod's own rotating token for reads, a token minted per action for writes.

Reads

The Kubernetes proxy, the catalog ingestor and the pollers send the pod's projected token (audience kiac-dev, 600 s). kiac-dev maps it to hangar:kind-prod:backstage-ingestor, which can only read.

Writes

Re-run, Cancel, release and rollback runs (all through glidepath-api since P6, 2026-10-30) and break-glass ask kind-prod for a 10-minute tower-actor token per action and drop it after. Only hangar:kind-prod:tower-actor holds write grants: glidepath-api's service proxy and the debug-role binder.

Trust

kiac-dev fetches kind-prod's public keys from hangarplatform.dev/oidc/kind-prod. Deleting the jwt entry in its authentication config cuts Backstage off within seconds.
