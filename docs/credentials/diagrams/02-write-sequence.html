Cluster credentials · 02 · Sequence

A Tower write, end to end

Re-run on a PipelineRun, from the click to the new run. The write token exists for this one action: minted after the ownership check, used once to call glidepath-api, never stored. glidepath-api, not Tower, creates the run.

Before any token

The backend refuses a user who doesn't own the app (tower.pipeline.rerun, or .cancel), and records the refusal. No token is minted for a refused request.

The token

TokenRequest for backstage/tower-actor: audience kiac-dev, 600 s. Backstage's ServiceAccount may create tokens for that one name only. It holds no Tekton grant (since P6, 2026-10-30).

At kiac-dev

The token must come from kind-prod's issuer, carry audience kiac-dev, name backstage/tower-actor and live at most 600 s. Its RBAC opens only glidepath-api's service proxy. glidepath-api authorizes rerun on runs.glidepath.hangar.io and audits it; glidepath-api-pipelinerun-shape allows only Glidepath's own run shape in an app- or infra- -cicd namespace, and refuses any PipelineRun write from tower-actor.
